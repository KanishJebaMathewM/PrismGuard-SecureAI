## 1. Project Overview

**PrismGuard** is a full-stack AI security gateway that sits in front of one or more "resource databases" — Banking, Government, Company, and Research — and ensures every user prompt passes through a multi-layer security pipeline before any data is returned or an LLM is allowed to respond.

### Purpose

The platform protects AI-connected data systems from prompt injection, jailbreaks, data extraction, role manipulation, instruction override, bulk extraction, citation manipulation, data poisoning, and PII extraction attacks. It intercepts, classifies, logs, and optionally blocks every prompt before forwarding it to OpenAI GPT.

### Target Users / Industries

- **Financial institutions** (banking APIs, account management)
- **Government agencies** (civic databases, policy documents)
- **Enterprises** (internal HR, finance, legal documents)
- **Research institutions** (academic paper repositories, scientific datasets)
- **Security teams** who need an admin review workflow and continuous ML model retraining

### Goals

1. Block known attack patterns before they reach the LLM.
2. Provide a transparent, per-layer audit trail of every prompt.
3. Give admins a review queue to classify edge cases and retrain models continuously.
4. Support offline / fallback operation if backend services are unavailable.

## 2. High-Level Architecture

```
Browser (React 18 / TypeScript / Vite)
    │
    │  GET/POST /api/*  (Vite dev-server proxy → http://localhost:8000)
    ▼
FastAPI Backend (Python 3.11 / Uvicorn, port 8000)
    │
    ├── Layer 1: Keyword Filter   (in-process, no network call)
    ├── Layer 2: SecureAI Guard API  (external cloud, HTTPS POST)
    ├── Layer 3: PrismGuard ML Model (in-process .pkl inference)
    ├── Layer 4: Resource Model label (display step, same .pkl)
    └── Layer 5: OpenAI GPT-4o-mini  (external cloud, HTTPS POST)
    │
    ├── SQLite database (prismguard.db via SQLAlchemy)
    └── .pkl model files (backend/models/*.pkl via joblib)
```

### Layer Summary

| Layer | Where | Technology | Fail behaviour |
|---|---|---|---|
| Keyword Filter | FastAPI process | Python `str.lower()` + list scan | Hard-blocks immediately |
| SecureAI Guard API | Cloud (GCP europe-west4) | HTTP/JSON over `httpx` async | **Fail-open** — marks step `unavailable` and continues |
| PrismGuard ML Model | FastAPI process | scikit-learn `Pipeline` from `.pkl` | Fallback to label=0 if no model trained yet |
| Resource Model | FastAPI process | Same `.pkl` | Display-only step |
| OpenAI GPT | Cloud | `openai` Python SDK | Static fallback message |

## 4. Backend Deep Dive

### 4.1 Application Entry (`backend/main.py`)

FastAPI app, titled "PrismGuard ML Backend v1.0.0". Loaded by `uvicorn backend.main:app --reload --port 8000`.

**CORS middleware** reads `CORS_ORIGINS` from `.env` (default: `http://localhost:5173,http://localhost:3000`) and allows all methods and headers.

1. `load_dotenv` from project root `.env`

### 4.2 All API Endpoints

#### `GET /api/health`
Returns `{"status": "ok", "models_loaded": [...]}` — lists which of the 4 resource `.pkl` files exist on disk.

#### `GET /api/models`
Queries `model_metadata` table for all 4 resources. If a row is missing, returns a zero-state placeholder (`"status": "Untrained"`).

#### `GET /api/models/{resource}`
Returns metadata for one resource. 404 if resource name is invalid (case-insensitive match against `["Banking", "Government", "Company", "Research"]`).

#### `POST /api/models/{resource}/retrain`
Calls `retrain_model(resource, db)`. Returns `{success, version, accuracy, samples}`. 400 if not enough samples (`< 4`).

#### `GET /api/prompts`
Last 100 prompts across all resources, newest first.

#### `GET /api/prompts/{resource}`
All prompts for one resource, newest first (no limit).

#### `POST /api/prompts/predict`
**Request:** `{text: str, resource: str}`
**Response:** `{label: int, confidence: float, resource: str, fallback: bool}`
Calls ML model directly. Does not go through the full security pipeline.

#### `POST /api/chat` — **The main pipeline endpoint**
See Section 7 for the full trace. Request/response shapes:

```python
# Request
class ChatRequest(BaseModel):
    text: str
    resource: str

# Response
class ChatResponse(BaseModel):
    response: str
    blocked: bool
    blocked_reason: Optional[str]
    blocked_layer: Optional[str]
    resource: str
    security_steps: list[SecurityStepResult]
    sent_to_review: bool
    confidence: Optional[float]

class SecurityStepResult(BaseModel):
    name: str
    status: str  # 'passed' | 'blocked' | 'flagged' | 'unavailable'
```

#### `POST /api/admin/reviews/{review_id}/classify`
**Request:** `{prompt_text, resource, classification: "Malicious"|"Safe", category, notes}`
Stores the prompt in the `prompts` table then immediately calls `retrain_model`. Returns `{stored_id, resource, retrained, new_version, accuracy, message}`.

Note: `review_id` is accepted as a path parameter but is not used to look up an existing row — each classify call creates a fresh `Prompt` row. This is by design; the review queue is currently frontend-side state.

#### `GET /api/stats`
Returns total prompts, malicious/safe counts, and per-resource breakdown.

## 5. Secure AI / GuardRails Integration

### 5.1 What Secure AI API Is

This is **not** NeMo Guardrails, GuardrailsAI, or AWS Bedrock Guardrails. It is a **custom proprietary cloud API** called **SecureAI Guard**, hosted on Google Cloud Run in the `europe-west4` region:

```
Base URL: https://secureai-guard-598609297408.europe-west4.run.app
```

Authentication: Bearer token prefixed `sai_` (set in `.env` as `GUARD_TOKEN`).

### 5.2 Initialization and Configuration

`backend/guard_client.py` reads configuration at module import time:

```python
_BASE_URL = os.getenv("SECURE_GUARD_API_URL") or os.getenv("GUARD_URL", "")
_TOKEN    = os.getenv("SECURE_GUARD_TOKEN") or os.getenv("GUARD_TOKEN", "")
_TIMEOUT  = float(os.getenv("GUARD_TIMEOUT_SECONDS", "8.0"))
_MAX_RETRY = int(os.getenv("GUARD_MAX_RETRIES", "2"))
_PROMPT_ENDPOINT = "/v1/check/prompt"
```

No persistent client object is created — a new `httpx.AsyncClient` is instantiated per request (inside the `async with` block).

### 5.3 Where in the Pipeline It Is Called

Layer 2 of the `POST /api/chat` handler in `main.py`:

```python
guard_result = await guard_check_prompt(text, resource)
```

Called **after** the keyword filter (Layer 1) passes, and **before** the ML model (Layer 3). The `resource` parameter is passed to `check_prompt` but the current implementation does **not** include it in the API payload (only `text` is sent).

### 5.4 HTTP Request Shape

```http
POST https://secureai-guard-598609297408.europe-west4.run.app/v1/check/prompt
Authorization: Bearer sai_<token>
Content-Type: application/json

{"text": "<user prompt>"}
```

### 5.5 Response Parsing (`_parse_guard_response`)

The API returns a JSON body with this documented shape:

```json
{
  "allowed": true,
  "checks": {
    "injection": {
      "flagged": false,
      "confidence": "HIGH"
    }
  },
  "flags": ["injection"],
  "status": "complete"
}
```

Parsing logic:

1. **Primary signal**: `allowed` field — `blocked = not bool(data["allowed"])`.
2. **Fallback signals** (if `allowed` absent): checks `blocked`, `is_blocked`, `is_malicious`, `flagged`, `unsafe`, `result` in `("blocked","malicious","unsafe")`, `action` in `("block","deny","reject")`.
3. **Reason construction**: iterates `flags` array, reads per-flag `confidence` and `types` from `checks`, builds a human-readable string like `"Blocked by SecureAI Guard: injection (confidence: HIGH)"`.
4. **Confidence mapping**: `HIGH→0.95`, `MEDIUM→0.65`, `LOW→0.35` from the `injection` check's `confidence` field.

The parsed result is a `GuardResult` dataclass:

```python
@dataclass
class GuardResult:
    blocked: bool
    reason: str = ""
    confidence: float = 0.0
    raw: dict = field(default_factory=dict)
    unavailable: bool = False
```

### 5.6 Retry and Fail-Open Behaviour

- Retries up to `_MAX_RETRY` (default 2) times on network errors and non-2xx responses (except 403).
- **HTTP 403**: immediately returns `GuardResult(blocked=True, confidence=1.0)` — treats the service's own auth failure as a block.
- **Network timeout / connection error**: logs a warning and returns `GuardResult(blocked=False, unavailable=True)`.
- **Any unexpected exception**: also returns `GuardResult(blocked=False, unavailable=True)`.
- In `main.py`, when `guard_result.unavailable` is `True`, the step is recorded as `"unavailable"` and the pipeline continues (**fail-open**).

### 5.7 How Its Result Influences the Response

In `POST /api/chat`:

```python
if guard_result.blocked:
    # Hard block — return immediately, store as label=1, risk=High
    steps.append(SecurityStepResult(name="Secure AI API", status="blocked"))
    return ChatResponse(blocked=True, blocked_layer="Secure AI API Layer", ...)

elif guard_result.unavailable:
    # Soft pass — log warning, mark step unavailable, continue pipeline
    steps.append(SecurityStepResult(name="Secure AI API", status="unavailable"))

else:
    # Clean pass
    steps.append(SecurityStepResult(name="Secure AI API", status="passed"))
```

## 6. ML Models

### 6.1 What Each Model Does

There are four models, one per resource domain. Each is a binary classifier:

- **Label 0** = safe prompt
- **Label 1** = malicious / injection attempt

| Model file | Resource | Attack categories learned from seed data |
|---|---|---|
| `backend/models/banking_model.pkl` | Banking | Prompt Injection, Jailbreak, Data Extraction, Instruction Override |
| `backend/models/government_model.pkl` | Government | Prompt Injection, Role Manipulation, Data Extraction, Jailbreak |
| `backend/models/company_model.pkl` | Company | Prompt Injection, Data Exfiltration, Jailbreak, Instruction Override |
| `backend/models/research_model.pkl` | Research | Data Exfiltration, Restricted Access Bypass, Bulk Extraction, Prompt Injection, Jailbreak, Data Poisoning, Citation Manipulation, Instruction Override, Role Manipulation, PII Extraction |

### 6.2 Algorithm

Each model is a scikit-learn `Pipeline` with two steps:

**Step 1: `TfidfVectorizer`**
```python
TfidfVectorizer(
    ngram_range=(1, 2),   # unigrams + bigrams
    max_features=5000,
    sublinear_tf=True,    # log(1 + tf) instead of raw tf
    strip_accents="unicode",
    analyzer="word",
)
```

**Step 2: `LogisticRegression`**
```python
LogisticRegression(
    max_iter=1000,
    class_weight="balanced",  # compensates for class imbalance
    C=1.0,
    solver="lbfgs",
)
```

The model is trained on raw text strings (no tokenizer, no embeddings). The TF-IDF matrix captures word/phrase frequencies; Logistic Regression learns a decision boundary.

### 6.3 Training

`retrain_model(resource, session)` in `ml_models.py`:

1. Queries all `Prompt` rows for the resource from the SQLite DB.
2. Requires at least **4 samples** (returns `{"success": False, "reason": "not enough samples"}` otherwise).
3. If both classes are present and ≥10 total rows: splits 80/20 with stratification, fits on train set, scores on test set for accuracy.
4. Otherwise: fits on all rows, uses `100.0%` accuracy (single class) or `75.0%` (two classes, fewer than 10 samples) as a placeholder.
5. Saves the fitted pipeline to disk with `joblib.dump`.
6. Updates the `model_metadata` row (bumps minor version, e.g. `v1.0 → v1.1`, updates `training_samples`, `detection_accuracy`, `last_trained`).

Version bumping logic: splits version string on `.`, increments the second part.

### 6.4 Loading and Inference

**Loading** — lazy, cached. `_pipeline_cache: dict` holds loaded pipelines keyed by resource name. On first call to `predict(resource, text)`, `_load_pipeline` checks the cache, then tries `joblib.load` from disk.

**Inference**:
```python
label = int(pipeline.predict([text])[0])          # 0 or 1
proba = pipeline.predict_proba([text])[0]          # [p_safe, p_malicious]
confidence = float(proba[label])                   # confidence of the predicted label
```

**Fallback** — if no `.pkl` exists: returns `{"label": 0, "confidence": 0.5, "fallback": True}`.

### 6.5 How ML Output Feeds the Security Pipeline

In `POST /api/chat` (Layer 3):

```python
ml_result = predict(resource, text)
ml_label  = ml_result["label"]        # 0 or 1
ml_conf   = ml_result["confidence"]   # 0.0–1.0

if ml_label == 1 and ml_conf > 0.7:
    # HARD BLOCK — store as label=1, sent_to_review=True, return immediately
elif ml_label == 1 and 0.5 <= ml_conf <= 0.7:
    # SOFT FLAG — mark step "flagged", sent_to_review=True, but pipeline continues to LLM
else:
    # PASS
```

The `confidence` value is also returned to the frontend in `ChatResponse.confidence`.

## 7. Security Pipeline Flow (End-to-End Trace)

This traces a single user message from the browser all the way to the response.

### Step 0 — User Input (Frontend)

User types a message in `Chat.tsx`. If `selectedResource === "Auto Detect"`, `detectResource(text)` runs a simple keyword heuristic to pick a resource (e.g. `"interest"` → Banking). `handleSend(text, resource)` is called.

### Step 1 — API Call (Frontend → Backend)

`chatWithPrismGuard(text, resourceType)` is called from `src/api.ts`:

```http
POST http://localhost:5173/api/chat
  (Vite proxy) → http://localhost:8000/api/chat

Body: {"text": "...", "resource": "Banking"}
```

Vite dev-server forwards this via the `/api` proxy rule in `vite.config.ts`.

### Step 2 — Resource Validation (Backend)

`_normalise_resource(resource)` does a case-insensitive match against `["Banking", "Government", "Company", "Research"]`. Returns 404 if unknown.

### Step 3 — Keyword Filter (Layer 1)

```python
lower = text.lower()
if any(kw in lower for kw in _KEYWORD_BLOCKLIST):
    # Immediate block
    db.add(Prompt(text=text, resource=resource, label=1, risk="High", source="chat"))
    db.commit()
    return ChatResponse(blocked=True, blocked_layer="Keyword Filter", ...)
```

If blocked here: the prompt is stored, pipeline terminates, no external API calls are made.

### Step 4 — SecureAI Guard API (Layer 2)

```python
guard_result = await guard_check_prompt(text, resource)
```

`guard_client.py` sends `POST /v1/check/prompt` to the cloud endpoint. Returns a `GuardResult`.

- `blocked=True` → store prompt, terminate pipeline, `blocked_layer="Secure AI API Layer"`
- `unavailable=True` → log warning, step status = `"unavailable"`, continue
- `blocked=False` → step status = `"passed"`, continue

### Step 5 — ML Model (Layer 3 — PrismGuard)

```python
ml_result = predict(resource, text)
```

The in-process TF-IDF + LR pipeline from the `.pkl` file classifies the text.

- `label=1, confidence>0.7` → hard block, `sent_to_review=True`, terminate
- `label=1, 0.5≤confidence≤0.7` → soft flag, `sent_to_review=True`, step = `"flagged"`, continue
- Otherwise → step = `"passed"`, continue

### Step 6 — Resource Model Label (Layer 4)

This is a **display-only step** — it always appends `SecurityStepResult(name="Resource Model", status="passed")`. No additional computation is done here; the same ML model already ran in Layer 3. It exists to visually show users which domain model was used.

### Step 7 — LLM Response (Layer 5)

```python
response_text = await llm_generate(text, resource)
```

`llm_client.py` calls OpenAI GPT-4o-mini with a resource-scoped system prompt. Returns the model's text, or a static fallback if unavailable.

### Step 8 — Audit Log

```python
audit_source = "chat-review" if sent_to_review else "chat"
audit_label  = 1 if sent_to_review else 0
db.add(Prompt(text=text, resource=resource, label=audit_label, risk=audit_risk, source=audit_source))
db.commit()
```

Every prompt that reaches the LLM is stored. Flagged prompts are marked `label=1` and `source="chat-review"` so the admin can find them in the review queue (though note the admin review queue in the frontend is currently static data from `src/data.ts`, not a live API query).

### Step 9 — Response to Frontend

`ChatResponse` is serialised to JSON and returned. The frontend's `SecurityCheckVisualization` component renders the `security_steps` array as a horizontal pipeline showing each step's status.

### SecurityPipeline.tsx

The `<SecurityPipeline>` component (used on the Dashboard) is a **static display component** — it visualises the conceptual pipeline with 6 stages (User Prompt → Keyword Filter → Secure AI API → PrismGuard → Resource Model → Connected Resource). It does not show live data; it receives a `selectedResource` prop to label the final stage.

The **live** pipeline visualization is `SecurityCheckVisualization` inside `Chat.tsx`, which renders the actual `security_steps` array from the API response.

## 8. Database Schema

SQLite database at `backend/prismguard.db`. Managed by SQLAlchemy 2.0 with ORM models in `backend/database.py`. Two tables:

### Table: `prompts`

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | Auto-increment |
| `text` | TEXT NOT NULL | The prompt text |
| `resource` | TEXT NOT NULL | "Banking" / "Government" / "Company" / "Research" |
| `label` | INTEGER | 0 = safe, 1 = malicious. Default: 0 |
| `category` | TEXT NULL | Attack category (e.g. "Prompt Injection", "Data Exfiltration") |
| `risk` | TEXT | "Low" / "Medium" / "High" / "Critical". Default: "Low" |
| `source` | TEXT | "seed" / "chat" / "chat-review" / "admin". Default: "seed" |
| `notes` | TEXT NULL | Admin notes on the classification |
| `created_at` | DATETIME | `func.now()` at insert time |

**No foreign keys.** The `prompts` table serves dual purpose: training dataset AND audit log.

### Table: `model_metadata`

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | Auto-increment |
| `resource` | TEXT NOT NULL UNIQUE | One row per resource |
| `version` | TEXT | e.g. "v1.0", "v1.1". Default: "v1.0" |
| `status` | TEXT | "Active" / "Untrained". Default: "Active" |
| `training_samples` | INTEGER | Count of rows used in last training. Default: 0 |
| `detection_accuracy` | FLOAT | Accuracy % (0–100). Default: 0.0 |
| `last_trained` | DATETIME NULL | UTC timestamp of last retrain |
| `attacks_detected` | INTEGER | Incremented counter. Default: 0 |
| `created_at` | DATETIME | `func.now()` at insert time |

Note: `attacks_detected` is stored in the DB but **never incremented** in the current source code — it is always returned as 0 from the API (only set at creation).

## 12. Findings & Recommendations

These are observations from reading the code. No changes were made.

### Critical Security Issues

1. **`.env` file contains live secrets and is checked in.** `GUARD_TOKEN` and `LLM_API_KEY` are real credentials stored in plaintext in the repository. These should be rotated immediately and the `.env` file added to `.gitignore` (it is currently NOT in `.gitignore`).

2. **`MAX_INPUT_LENGTH` is not enforced.** The env var is set to 4000 but `POST /api/chat` accepts prompts of unlimited length. A very long prompt could be used to slow the Guard API and ML inference.

3. **`RATE_LIMIT_PER_MINUTE` is not enforced.** No middleware (e.g. `slowapi`) is installed. The endpoint is unthrottled.

4. **The keyword blocklist uses substring matching without word boundaries.** `"salary"` would match `"salary"` but also `"salary negotiation tips"` (intended) yet could also produce false positives on edge cases. More importantly, attackers can trivially bypass it with spacing variations or Unicode homoglyphs.

5. **Guard API is fail-open.** If the external SecureAI service is down or blocked, the pipeline continues without that check. This is documented and intentional, but it means a network-level attack against the Guard API degrades security to keyword + ML only.

### Functional Gaps

6. **Admin review queue is disconnected from the backend.** The `AdminReview.tsx` screen reads from `reviewQueue` in `src/data.ts` (hardcoded static data), not from `GET /api/prompts` filtered by `source="chat-review"`. Quick-classify buttons do call the API but the list of items to review is always the static seed data.

7. **`attacks_detected` is never incremented.** The `model_metadata.attacks_detected` column defaults to 0 and no backend code increments it. The Dashboard and Models screens display this as always 0 from the live API.

8. **AttackLab does not call the backend.** The "Run Security Test" button simulates a hardcoded result (always blocked at PrismGuard layer). To be a genuine test harness it should call `POST /api/chat`.

9. **Models screen retraining is a UI simulation.** The "Start Retraining" progress bar in `ModelDetail` is a `setInterval` timer, not a real API call to `POST /api/models/{resource}/retrain`.

10. **`@supabase/supabase-js` is installed but unused.** It appears in `package.json` dependencies but is not imported in any source file, adding dead weight to the bundle.

11. **`GUARD_RESEARCH_BUDGET`, `AUDIT_LOG_JSONL_PATH`, and `RESEARCH_RESULTS_PATH`** are set in `.env` but not read by any backend module.

12. **The `resource` parameter is not forwarded to the Guard API.** `guard_client.py` receives `resource` as a parameter but only sends `{"text": text}` in the payload. If the Guard API supports context-aware checking, this is a missed opportunity.

### Recommendations

- Rotate the credentials in `.env` immediately and add `.env` to `.gitignore`.
- Add `slowapi` or FastAPI's `Depends` rate-limiting middleware using `RATE_LIMIT_PER_MINUTE`.
- Add a `MAX_INPUT_LENGTH` check at the top of `POST /api/chat` and `POST /api/prompts/predict`.
- Add `GET /api/admin/reviews` endpoint that returns `prompts` rows where `source IN ("chat-review")` and `label=1`, so the AdminReview screen can show live data.
- Increment `attacks_detected` in `model_metadata` when a prompt is hard-blocked.
- Wire AttackLab's "Run Security Test" to `POST /api/chat` for genuine testing.
- Wire ModelDetail's "Start Retraining" to `POST /api/models/{resource}/retrain`.
- Remove or use the `@supabase/supabase-js` dependency.
- Pass `resource` in the Guard API payload if the cloud API supports it.
- Consider adding word-boundary checks or more sophisticated NLP to the keyword blocklist to reduce bypass risk.
